# ADR 0004：Agent 评估策略（规则判定为主）

- 状态：已接受
- 日期：2026-10-13

## 背景

需要一套可重复、可回归的 Agent 质量判定方式，用于 Prompt、模型适配、工具与解析逻辑改动后
判断是否退化；同时要避免把不可复现的主观评价当成唯一验收依据。

## 决策

1. **规则判定为主**：`evals/checks.py` 定义确定性检查（来源真实性、无效引用、
   密钥泄露、失败伪装、截断透明、复用行为、工具错误类别、调用次数上限），
   每项输出通过/失败与证据文本。
2. **固定案例集**：`evals/cases/core.json` 维护 12 个案例，覆盖正常、异常、安全与引用场景；
   每个案例声明文档来源（真实 URL 或本地可控页面）、用户消息、可选的追问与检查清单。
3. **真实模型执行**：评估默认调用真实模型与真实文档（本地可控页面用于失败路径），
   不 mock 端到端结果；检查器本身用确定性夹具自测。
4. **回归比较**：结果写入 JSON，`--baseline` 与既有基线逐案例比较，
   「基线通过、本次失败」即判定回归并以非零退出码结束。
5. **模型主观评价仅作辅助**：如引入模型评审，只能作为附加信息，不作为通过/失败依据。

## 备选方案

- 只用模型自评：不可复现、成本高，且难以定位退化原因。
- 只做人工检查：无法在每次改动后快速回归。

## 影响

- 评估运行会产生模型费用，属于**可选**的付费检查（默认测试套件不含评估运行）。
- 新增能力时要同步补充检查器或案例，否则退化可能漏检。
- 真实文档页面结构变化会影响个别案例，需要定期核对基线。
